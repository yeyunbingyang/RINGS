# 前端优化

## 先找规则，再审查

- 读取[前端审查打卡](references/review.html)中的 rule-data。它是已确认规则的唯一来源。按分类和适用范围挑出规则，引用稳定编号，例如 R01。
- 查看用户截图、需求和当前页面。能运行时，在约定的目标尺寸和页面状态下检查实际操作。每项发现记录位置、触发条件、证据和用户影响。证据不足记为「待查」，确认问题记为「待优化」，验证符合记为「通过」，范围外记为「不适用」。
- 按影响排序，优先处理读取、操作、保存或数据正确性问题。没有匹配规则时，仍按现有需求和证据审查，把可复用做法列为候选，等用户确认后加入。

## 三个方案和效果图

- 每个新的前端优化主题给出 **三个**有实际差异的完整方案，说明对应的规则、适用场景和取舍，并推荐其中一个。
- **每个方案直接附一张可见的效果图**。使用同一目标页面、窗口尺寸和示例数据。现有界面优先用真实组件或 HTML 渲染，截图涵盖此次比较区域和必要操作入口。示例数据注明用途。
- 用户要求先看图或选择时，选定前保持正式页面源码不变。用户选定并要求实施后，按选择落地，用真实页面截图和关键操作复审。

## 打卡和可视化审查

- 用户要求打卡时，在打卡页选择或建立对应的项目或页面记录。通过浏览器操作「批量打卡」，例如输入 R01 R02 通过；R06 待优化：晚间时间未显示。状态必须来自用户明确给出的结论或实际验收证据。用明确项目和规则编号定位，避免记错审查批次。
- 审查记录保存在实际操作该页的浏览器和访问地址。当前无法操作用户所用页面时，给出可粘贴的打卡指令，并说明未写入。可通过「复制结果」交付当前记录。
- 新增已确认规则时只维护 review.html 的 rule-data，填入编号、分类、标题、适用范围、执行要求和验证方式。已有编号保持稳定，新增分类由面板自动生成。候选规则以清单单独交付，经用户确认后再加入。
