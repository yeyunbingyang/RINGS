# CAP-02 规划能力

> 所属层：规划层 Planning  
> 优先级：P0  
> 状态：核心实体与边界已纳入 PRD；v0.8 规划工作区原型首轮完成（prototype_only）；指标口径已形成设计方案，待用户评审；正式持久化未实现。

## 1. 能力目标

帮助用户明确长期发展方向，将方向转化为可衡量目标，再把目标拆分为可管理的阶段，并与执行任务关联。

## 2. 子能力

| 编号 | 子能力 |
|---|---|
| CAP-02-01 | Direction 发展方向管理 |
| CAP-02-02 | Goal 目标管理 |
| CAP-02-03 | 目标衡量指标和完成条件 |
| CAP-02-04 | Stage 阶段拆分与排序 |
| CAP-02-05 | Goal / Stage 与 Task 关联 |
| CAP-02-06 | 目标进度自动计算（增强） |

## 3. Direction（发展方向）

定义：长期希望投入、提升或发展的领域。

示例：职业发展、AI 技术能力、软件工程、英语能力、健康管理、个人创作。

规则：
- 不强制设置截止日期。
- 可以关联多个 Goal。
- 可以只有描述，不立即创建 Goal。
- 可暂停或归档，不影响历史 Goal。

## 4. Goal（目标）

定义：在一定时间内希望达到的、可描述和衡量的结果。

建议字段：名称、说明、所属 Direction、指标类型、当前基线、目标值、单位、开始日期、目标期限、完成判定条件、状态和当前进度。

指标类型建议：数值、里程碑、布尔完成、自定义。最终类型待决策。

规则：
- Goal 表示结果，不等同于 Task。
- 目标进度不能简单等于任务完成率。
- 有量化指标时优先依据指标计算。
- 里程碑型目标可参考 Stage 完成情况。
- 用户可以手动更新进度。

## 5. Stage（阶段）

定义：实现一个 Goal 过程中划分的阶段性工作过程。

示例：找到一份合适的新工作：
1. 职业定位。
2. 求职准备。
3. 投递与面试。
4. Offer 评估与入职。

建议字段：goal_id、title、description、sort_order、start_date / due_date（可选）、exit_criteria、status / progress。

规则：
- 一个 Goal 可以有多个 Stage。
- Stage 可以关联多个 Task。
- Stage 可以没有固定时间。
- Stage 应有可判断的完成条件或交付结果。
- Stage 完成不等于 Goal 完成。
- 阶段状态可直接编辑为未开始、进行中、受阻或已完成。任务、阶段和目标分别确认完成。
- 阶段支持独立标签、清单与资料，可关联未归属或同目标的任务。删除阶段时，同目标任务改为直接归属目标，清单及资料移入目标。
- Task 可直接关联 Goal，不强制必须归属 Stage。
- 桌面规划页提供目标与阶段搜索，以及直接点击的排序选项。新建任务时，可关联目标在 6 项以内直列，7 项起提供可搜索的下拉。

## 6. 页面建议

- Direction 列表 / 详情。
- Goal 列表 / 详情。
- Stage 时间线或阶段看板。
- Goal 详情中显示指标、阶段、关联任务和补充资料。
- Goal 详情可直接打开关联任务的执行详情。
- 目标可从卡片双击或详情按钮重新编辑，支持标签、备注、清单和分组资料。
- 首页仅展示目标摘要和里程碑；完整编辑在规划工作区。

## 7. 核心流程

```text
创建 Direction（可选）
    ↓
创建 Goal
    ↓
定义目标指标、期限和完成条件
    ↓
拆分 Stage
    ↓
为 Stage 创建或关联 Task
    ↓
Task 进入执行层
    ↓
回看 Stage 结果和 Goal 指标
```

## 8. 验收要点

- [ ] Direction 可独立存在，不强制期限。
- [ ] Goal 可设置衡量指标和完成条件。
- [ ] Goal 可拆分多个 Stage。
- [ ] Stage 可以关联多个 Task。
- [ ] Task 可以直接关联 Goal。
- [ ] 不强制所有 Task 归属 Goal。
- [ ] Stage 完成不自动等于 Goal 完成。
- [ ] Goal 进度口径可解释，不简单等于任务完成率。


## 9. Goal 创建时的可选 Stage

创建 Goal 时允许用户选择是否同时建立子阶段（Stage）。Stage 可以逐条添加、编辑、删除和排序；不建立 Stage 不影响 Goal 保存。Stage 是 Goal 的规划结构，不因创建而自动生成 Task。

原型状态：prototype_only；Stage 与 Goal 的持久化关系仍需在正式数据层实现。


## 10. v0.8 指标与进度细化

原型提供四种 Goal 衡量方式：
- 数值指标：按基线、当前值和目标值计算，支持递增 / 递减。
- 里程碑：已完成 Stage 数 / Stage 总数；各 Stage 当前等权。
- 布尔结果：由用户明确确认是否达成。
- 自定义进度：用户手动维护 0–100%。

Goal 进度与关联 Task 完成率分开显示；Task 完成率不参与 Goal 进度计算。Stage 全部完成不自动关闭 Goal。没有 Stage 的里程碑目标显示 0%。

以上是 v0.8 原型方案，Stage 加权、Goal 多指标、历史快照和自动进度策略仍待评审。
