# CAP-01 捕捉能力

> 所属层：捕捉层 Capture  
> 优先级：P0  
> 状态：核心业务基线已确认；附件存储细节待决策。

## 1. 能力目标

将临时出现的信息、资料、想法、愿望、问题和责任事项统一捕捉为 Candidate，避免录入时过早要求用户决定执行方式。

在候选事项页，单击分类筛选，双击具体分类或点击右上角对应的捕捉按钮可打开已预选该分类的弹窗。保存时以弹窗里的最终选择为准。

## 3. Candidate 分类

1. 备忘（Memo）
2. 资料（Resource）
3. 想法（Idea）
4. 愿望（Wish）
5. 待办种子（Task Candidate）
6. 问题（Issue）
7. 待决策（Decision）
8. 承诺（Commitment）
9. 事件（Event）
10. 等待（Waiting）

默认一个主要分类，可叠加自定义 Tag。分类显示中文名称（English）。

## 4. 详情结构

建议 Candidate 详情至少包含：
- 基本信息：名称、分类、标签、来源。
- 备注记录：多条列表，支持新增、编辑、删除、排序。
- 补充资料：图片、媒体、文档、其他文件、网页链接、文件和文件夹路径。
- 时间信息：Deadline Hint、Event Time、Reminder Time、Follow-up Time、Review Time。
- 关联事项：相关 Candidate、Goal、Task、Event 等。
- 生命周期：保留、孵化、转换、归档、取消。

## 5. 补充资料规则

**Managed Attachment：** 由 RINGS 保存文件副本。原始文件不应未经确认被移动或删除。需记录文件名、类型、大小、添加时间和存储位置。

**External Reference：** 只保存 URL、URI 或路径。适用于网页、GitHub、云盘、本地文件、网络共享目录和文件夹。

文件夹引用默认不复制、不递归扫描；支持打开、检查、重新定位；失效时保留记录；可关联多个业务对象。

## 6. 时间信息

Candidate 可有时间信息，但必须区分：
- 截止时间：是否已经形成明确行动责任。
- 事件时间：是否需要转为 CalendarEvent。
- 提醒时间：提醒自己查看。
- 跟进时间：等待事项下一次检查。
- 回顾时间：重新评估候选事项。

仅有日期不自动转换为 Task。

## 7. 核心流程

```text
快速输入标题 / 内容
    ↓
创建 Candidate
    ↓
可选分类、标签、备注、补充资料
    ↓
留在统一候选池
    ↓
用户回顾：保留 / 孵化 / 归档 / 关联 / 转为 Task / Goal / Event
```

## 8. 验收要点

- [ ] 快速捕获不要求填写大量字段。
- [ ] 十种分类可在同一个 Candidate Pool 管理。
- [ ] 分类使用中文名称（English）。
- [ ] 每条 Candidate 支持多条备注。
- [ ] 支持标签、搜索、筛选和排序。
- [ ] 支持明确区分不同时间语义。
- [ ] 支持网页、文件和文件夹引用。
- [ ] 文件夹引用默认不复制、不扫描目录。
- [ ] 支持附件副本与外部引用的区分。
- [ ] Candidate 转换后保留来源关系。
- [ ] 归档可恢复；不要求每日清空候选池。

## 9. 待决策

- 十种分类是否严格单选。
- 图片 / 视频 / 文档的应用内副本存储策略。
- Candidate 的回顾提醒频率和默认值。
- Resource 是否需要独立的知识库视图。


## 10. 首页快速资料收藏交互补充（原型 v0.7）

顶部导航提供快速资料收藏入口，复用快速捕捉表单。以候选事项保存时只需名称，标签、备注、清单和文件资料可选，分类固定为「资料（Resource）」。

主动选择、拖入或粘贴的文件保存为附件副本。外部链接和路径按 External Reference 规则处理，只保存引用。

清单中的常见图片附件显示缩略图，点击可查看完整图片。文件读取或解码失败时提示下载原文件。图片预览沿用清单的新建、编辑和只读详情，其他附件保留下载。

新建与编辑共用「基础信息」「清单」两个页签。标签、备注和来源集中在基础信息。收藏资料的候选事项固定为「资料」，捕捉时免选分类。

「清单」左侧列出条目和资料数量，右侧编辑选中项。一项可独立填写多行说明、添加多个文件、录入多个链接或路径。至少填写一类内容，说明留空时用文件名、网址域名或路径末级生成列表名。外部引用可标记为来源或整理目标，可移动到本记录的其他清单。旧的事项级资料归入「原有资料」，删除含资料的清单时确认后也将资料保留在该条目。转换为任务时只复制手写说明为子任务，文件和引用仍可通过来源候选事项查看。

原型状态：prototype_only；正式存储和资料管理列表尚未实现。


## 11. v0.3 Candidate 生命周期与转换补充

- Candidate 分类与生命周期独立：分类表达内容类型，状态表达处理进度。
- 支持编辑、搜索、备注增删、分类 / 状态筛选、批量归档和批量添加 Tag。
- Candidate 可转换为 Task、Goal、CalendarEvent，用户必须显式选择目标类型并确认。
- 转换后保留 Candidate 原记录、备注、标签、资料引用及来源关系。
- 删除来源 Candidate 不自动删除已经创建的正式对象。
- v0.3 原型已覆盖上述主要交互；附件上传、文件副本存储和真实对象服务仍待实现。


## 12. v0.3.1 资料列表交互

Candidate 详情增加资料列表。用户可拖动文件、粘贴剪贴板文件 / 图片或通过文件选择器添加，形成列表项；支持排序、移除和打开 / 下载。本机服务模式已使用受控附件存储服务：附件以原始字节写入 `data/attachments/`，工作台只保存引用，文件大小不设上限。正式应用仍需补充内容哈希、来源和权限信息；不得未经用户同意读取或上传外部路径内容。
