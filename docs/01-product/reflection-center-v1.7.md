# RINGS 复盘中心 PRD 补充规格 v1.7

> 版本：v1.7.0（复盘中心）+ v1.7.1（业务事件追溯）  
> 状态：HTML 原型已完成浏览器冒烟验收；正式应用尚未实现。  
> 设计确认：每周优先；数据分析独立标签；覆盖任务、习惯、目标、时间安排。

## 1. 背景与问题

旧版「复盘与统计」将统计卡片、趋势图和复盘笔记混在一起，无法清晰区分客观事实与主观判断；Task 与 Plan 统计口径混用；计划时长被误当作实际投入；习惯缺少记录被误判为未执行；目标当前进度被误读为周期内进度。

v1.7 将模块重构为「复盘中心」，形成周期复盘、数据分析、历史复盘、改进追踪四个独立区域。

## 2. 产品目标

1. 统计与复盘分离：统计只呈现可确认事实，复盘由用户分析原因和结论。
2. 默认每周复盘，同时支持每日、每月、自定义日期范围。
3. 任务、习惯、目标、时间安排全部纳入。
4. 每次复盘独立保存，保留当时的数据快照。
5. 把结论转为可追踪改进项，不自动改动用户任务和日程。
6. 对缺失、估算、不可确认的数据明确标注，不制造虚假精确。

## 3. 信息架构

### 3.1 周期复盘（默认）

顶部提供周期类型、日期范围、上一周期和下一周期。每周采用周一至周日自然周。

周期事实包括：
- Task：周期内创建、完成、当前进行中等事实；完成数按 Task 去重。
- Plan：周期内计划数、完成标记、取消和废弃；Plan 不等同于 Task。
- 时间：Plan 计划投入与 Execution Session 实际投入分开。
- Habit：只统计明确提交的量词记录；未记录不等于未执行。
- Goal：当前阶段进度可以展示，但必须标明是当前状态；周期变化必须依赖历史事件。

复盘表单五步：
1. 本周期取得了哪些成果？
2. 哪些事情没有按计划进行？
3. 产生这些偏差的原因是什么？
4. 本周期有哪些经验值得保留？
5. 下一周期准备采取什么行动？

支持保存草稿、完成复盘、重新打开和编辑。

### 3.2 数据分析

独立于复盘表单，不要求用户填写结论。展示任务、计划、时间、习惯和业务变更记录。

### 3.3 历史复盘

每个周期生成独立 Review，按周期开始日期倒序展示。保存文本、状态、快照、创建和更新时间。

### 3.4 改进追踪

支持新建、标记完成、重新打开和删除。改进项可记录来源 Review。当前原型不自动创建 Task 或修改 Goal。

## 4. 统计口径

### 4.1 Task 与 Plan
- Task 是执行事项，Plan 是一次时间安排；一个 Task 可有多个 Plan。
- Task 完成数按实际完成事件 / 可信 actualEndAt 去重。
- Plan 完成状态单独统计；取消和废弃计划单列，不进入有效计划完成率分母。
- 仅凭当前 Task 状态，不得推断其历史完成时间。

### 4.2 时间
- 计划投入来自周期内有效 Task Plan 的 duration。
- 实际投入来自 Execution Session。
- 精确、估算、未记录分别统计。
- 未记录不视为 0；估算不伪装成精确。
- 异常中断期间不计入实际投入。

### 4.3 习惯
- 实际量来自明确保存的 Habit history 记录。
- 未记录与明确未执行必须区分。
- 应执行次数须依据习惯重复规则；规则信息不足时显示不可计算，不用周期天数简单乘算。

### 4.4 目标
- 当前阶段完成比例仅代表当前状态。
- 周期内进展必须由 Stage 新增、完成、修改等历史事件计算。
- 缺少历史事件时明确显示不可追溯。

## 5. 数据模型

### Review
`id`、`period`（day/week/month/custom）、`startDate`、`endDate`、`status`（draft/completed）、`achievements`、`deviations`、`causes`、`insights`、`nextActions`、`snapshot`、`createdAt`、`updatedAt`。

### Review Snapshot
Task 创建/完成数量；Plan 总数/完成标记/取消/废弃；计划分钟数；精确/估算/未知 Session 数量及分钟数；习惯记录明细；目标当前状态；周期业务事件计数。

### Improvement
`id`、`title`、`sourceReviewId`（可选）、`status`（open/done/paused）、`createdAt`、`updatedAt`。

## 6. v1.7.1 业务事件历史

本版本增加轻量追加式业务变更日志，属于审计 / 变更历史，不是完整 Event Sourcing。

覆盖 Task、Plan、Habit、Goal、Candidate 的创建、修改、删除和状态变化；另记录 Task Session 新增、Habit 量词记录新增 / 修改、Goal Stage 变化。

事件包含实体类型、实体 ID、动作、检测时间、显示标题、精简前后摘要及必要变更字段。最多保留最近 1,000 条精简事件，独立存储，避免重复保存完整任务和 Session 对象。

旧数据载入后，在字段规范化和异常 Session 恢复完成后建立初始基线，不伪造历史创建事件。事件时间表示原型检测并持久化变更的时间，不承诺毫秒级操作审计。删除事件保留删除前精简摘要。

存储键：
- 业务数据：`rings-data-v171`
- 事件日志：`rings-event-log-v171`
- 迁移读取：`rings-data-v16`、`rings-data-v15`、`rings-data-v14`

本地原型不提供防篡改、跨设备审计或数据库事务保证。正式应用仍需服务端 / 数据库事件日志、备份和迁移策略。

## 7. 交互与非目标

- 默认每周复盘。
- 统计与周期复盘为独立标签。
- 草稿不等于完成。
- 历史记录可重新打开。
- 改进项完成后可重新打开。
- 不自动创建任务、不自动移动 Plan、不自动修改目标。
- 支持桌面和窄屏。
- v1.7.1 不宣称旧历史可完整追溯；没有可靠数据就明确标记。
