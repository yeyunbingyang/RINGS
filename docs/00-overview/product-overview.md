# RINGS 产品总览

> 状态：产品定位与核心架构已确认；详细 UI、技术方案仍需评审。

## 1. 品牌与定位

| 项目 | 定义 |
|---|---|
| 品牌 | RINGS |
| 中文名称 | 年轮 |
| 品牌意象 | 积累、时间沉淀、持续成长 |
| 产品定位 | 个人事务与成长管理系统 |
| 产品形态 | Desktop / Web |
| 核心理念 | 捕捉、规划、执行、调度、复盘 |

RINGS 不只是 Todo 列表，也不只是番茄钟。它管理个人信息、行动责任、长期目标、日常习惯和时间安排。

## 2. 用户核心问题

1. 临时出现的信息、资料、想法和事项需要快速保存。
2. 有些事项尚未决定是否执行，不应立即变成任务。
3. 长期方向需要形成可衡量目标，并拆解为阶段。
4. 已确认的行动需要任务、子任务和习惯管理。
5. 任务可能没有明确执行时间，需要在合适时机安排。
6. 需要同时观察今天、本周、本月和年度安排。
7. 执行结果、思考和资料需要能够沉淀、回顾和恢复。

## 3. 五层业务体系

| 层级 | 职责 | 核心对象 |
|---|---|---|
| 捕捉层 Capture | 收集尚未整理或尚未承诺的事项 | Candidate |
| 规划层 Planning | 组织长期方向、目标和阶段 | Direction、Goal、Stage |
| 执行层 Execution | 管理已确认的行动和重复行为 | Task、Subtask、Habit、WorkSession |
| 可视化调度层 Visual Scheduling | 将执行层任务安排到时间维度 | Plan、Calendar Event、Timeline |
| 管理层 Management | 分类、关联、归档、回顾、统计和备份 | Collection、Tag、Relation 等 |

五层是职责划分，不是强制线性流程。临时任务可以直接创建在执行层；习惯可以独立存在；事件可以不关联目标。

## 4. 默认首页

可视化调度层是默认首页和日常操作中心。首页核心区域：
1. 时间范围导航：今日 / 本周 / 本月 / 年度。
2. 快速创建：捕捉事项、任务、目标、习惯、事件、资料引用。
3. 主时间视图：显示 Plan、Calendar Event 和 HabitOccurrence。
4. 未安排任务池：显示已确认但尚未安排的 Task。
5. 今日执行摘要：完成情况、实际投入、习惯记录。

用户可以把未安排任务拖到某一天或具体时间段。拖放创建或更新 Plan，不创建重复 Task。

## 5. 核心工作闭环

```text
快速捕捉 Candidate
        ↓
澄清、保留、归档或转换
        ↓
规划 Direction / Goal / Stage（需要时）
        ↓
创建或确认 Task / Habit
        ↓
在首页把 Task 安排为 Plan
        ↓
开始 WorkSession / 完成 HabitOccurrence
        ↓
记录结果、Thought 和 WorkContext
        ↓
Review / Statistics / 下一轮调整
```

用户可以从任意入口开始，不强制每项事务经过全部步骤。

## 6. 产品原则

- 快速捕捉优先，不要求录入时完成所有分类。
- Candidate 不等于 Task。
- 分类与生命周期状态分离。
- Goal 表示结果，Task 表示行动。
- Habit 是重复规则，每次执行单独记录。
- Plan 是安排，WorkSession 是实际执行。
- Deadline 不等于 Plan Time。
- Candidate 池不要求每日清空。
- 归档可恢复，不等于删除。
- 附件副本与外部引用明确区分。
- Desktop / Web 共用核心领域模型，平台能力分别适配。
- 不把旧原型展示的交互视为正式代码已经实现。
