# RINGS v1.0.1 双端运行验收清单

> 目标：在 Windows 本机完成 Web 与 Desktop 的真实运行、持久化和重启恢复验证。
> 当前状态：自动化 CI 已通过；本清单等待本机执行。

## 1. 环境准备

- Node.js 22.12 或更高的 22.x LTS 版本。
- pnpm 10.x。
- Rust stable 工具链，最低 1.90。
- Windows C++ Build Tools 和 WebView2 Runtime。
- 已安装 Git。

从仓库根目录执行：

```powershell
git fetch origin
git switch feat/v1.0-desktop-web-foundation
git pull --ff-only
pnpm install
pnpm verify
```

CI 已生成依赖锁文件。可从 [本次 CI 运行记录](https://github.com/yeyunbingyang/RINGS/actions/runs/44755239755) 的 Artifacts 下载 rings-dependency-lockfiles，解压到仓库根目录，得到 pnpm-lock.yaml 和 apps/desktop/src-tauri/Cargo.lock。提交锁文件后，后续安装应使用 pnpm install --frozen-lockfile。

## 2. Web 运行验收

启动：

```powershell
pnpm dev:web
```

打开 http://localhost:5173。

测试步骤：
1. 新建一条任务，名称使用 QA-WEB-日期。
2. 为该任务安排一个未来时间段。
3. 点击“专注”，再点击“结束专注”。
4. 确认近期计划和实际执行记录均出现。
5. 刷新浏览器页面。
6. 确认任务、计划和执行记录仍然存在。

可在浏览器开发者工具的 Application → IndexedDB → rings-v1 中查看 tasks、plans、workSessions 三个对象存储。

## 3. Windows Desktop 运行验收

启动：

```powershell
pnpm dev:desktop
```

测试步骤：
1. 确认窗口标题为 RINGS · 年轮。
2. 新建一条任务，名称使用 QA-DESKTOP-日期。
3. 创建计划并执行一次专注。
4. 结束专注，确认实际执行记录出现。
5. 完全退出桌面应用。
6. 重新运行 pnpm dev:desktop。
7. 确认任务、计划和执行记录仍然存在。

Desktop 使用 SQLite 数据库 rings.db，保存在 Tauri 应用配置目录。

## 4. 业务约束验收

- 创建两个时间重叠的计划：第二条计划应先提示冲突。
- 取消第一条计划后：该已取消计划不再阻止新计划。
- 对同一任务同时启动两次专注：只允许一条活动 Session。
- 专注尚未结束时：不允许完成任务或移入回收站。
- 移入回收站后：任务从有效列表隐藏，但关联 Plan 和 WorkSession 保留。
- 恢复任务后：原任务 ID、计划和执行历史均保留。

## 5. 双端数据边界

Web 使用浏览器 IndexedDB；Desktop 使用本地 SQLite。两端数据独立，不会自动同步。

在 Web 创建 QA-WEB 任务后，不应期待它自动出现在 Desktop；反之亦然。
