# RINGS 恢复版需求审查清单

审查基准为 [PRD v2.2.2](../01-product/prd.md)、[信息架构](../02-design/information-architecture.md)、各模块现行规格及[需求追踪矩阵](traceability.md)。实现基准为用户提供的 [Recovery v1.7.1 + Gantt](../../prototypes/workspace-recovery/index.html)。本文区分恢复版的实际行为与其他版本曾交付过的能力。

## 已完成

- [x] 已以用户附件建立恢复版基准，ToolOrbit 插件和热更新预览共用该入口。下列差异记录审查时的状态，优化结果记录在后文。
- [x] 浏览器验证六个一级入口、默认调度首页、日周月年切换、规划甘特图打开与关闭、复盘四个标签和草稿持久化。
- [x] 390 像素宽度下检查六个页面，页面根元素无横向溢出。
- [x] 验证源码变动触发浏览器自动刷新、ToolOrbit 正式 WebUI 内嵌、独立启动、健康检查和同源停服。

## 优化前的需求差异

| 优先级 | 项目 | 恢复版实际行为 | 验收口径 |
| --- | --- | --- | --- |
| 高 | 删除与恢复 | 任务、习惯、候选事项和主工作台目标直接删除。删除任务会移除关联排期。内嵌规划原型自己的目标回收站与主工作台独立。 | 统一回收站保留对象与关系快照，支持恢复。永久删除单独确认，历史 Plan 和 WorkSession 有明确保留规则。见 [执行与候选事项 v0.3](../02-design/execution-candidate-v0.3-spec.md#6-删除归档和恢复)。 |
| 高 | 规划与调度数据 | 甘特图是内嵌独立原型，使用 `rings-planning-v08`。主工作台使用 `rings-data-v171`，两边没有同步代码。 | 同一 Task 和 Plan 在列表、甘特图与调度页可追踪，改期保留任务 ID，Deadline 独立。见 [规划 v0.9](../02-design/planning-workspace-v0.9-spec.md)。 |
| 高 | 导出和备份 | 设置可导出核心演示数据与导航配置。导出内容未包含复盘、改进事项、业务事件日志和内嵌甘特图数据，未见导入恢复入口。 | 明确备份范围，按范围验证导出和恢复，外部引用只备份引用信息。见 [管理层需求](../01-product/capabilities/CAP-05-management.md)。 |
| 中 | 候选事项转换 | 有转换为 Task 或 Goal 的按钮，正式对象保留来源 ID。没有转换为 Direction 或 CalendarEvent 的入口。 | 提供四种目标，显式确认后转换，保留来源和目标关系。见 [执行与候选事项 v0.3](../02-design/execution-candidate-v0.3-spec.md#5-candidate-转换)。 |
| 中 | 资料附件 | 本机服务模式通过 `/api/attachments/` 保存原始文件，工作台只保存引用；浏览器原型模式仍将 Data URL 写入 localStorage。 | 复验文件内容保存、下载、移除与备份范围；大附件不进入 JSON 备份，需同时备份 `data/attachments/`。见 [v0.3.1 附件规格](../02-design/execution-candidate-v0.3.1-spec.md#1-candidate-资料附件列表)。 |

## 优化完成与验证

- [x] 设置增加统一回收站。可恢复任务、习惯、候选事项、目标或日历事件，永久删除需确认。浏览器已验证删除并恢复任务及原排期。
- [x] 甘特图从当前工作台读取任务、目标和排期，并将改期写回。浏览器已验证两边使用同一计划 ID，改期保留开始时间，也保留旧版未绑定任务的时间块。旧版独立甘特数据保留并纳入备份，现行计划按主工作台记录显示。
- [x] 添加完整 JSON 备份和校验后导入，覆盖复盘、改进事项、业务事件日志、偏好、回收站以及规划数据。已从导出的内容还原包含附件的核心数据并核对复盘和日志。
- [x] 候选事项支持确认转为任务、目标、方向或日历事件，并记录双向来源关系。四种路径均已验证。
- [x] 附件保存内容并提供排序和下载。本机服务模式已取消文件大小限制，改为独立文件存储；已验证附件保存、下载和删除，旧 Data URL 附件仍可从备份恢复。
- [x] 独立插件已验证加载工作台、甘特图和备份模块，并正常退出。正式桌面端仍待走查。

- 「执行管理」对应信息架构里的「执行库」，「复盘与统计」对应页面标题「复盘中心」。走查使用恢复版显示的菜单名。
- [进度记录](../04-delivery/progress.md)中的 v0.3、v0.3.1、v0.9 和 v1.7.1 分别对应独立交付。软删除恢复和附件验收等记录仍归原版本，不能作为整合恢复版的验收证据。
- 正式应用的首发平台、数据库、API 和附件存储方案仍按现有决策记录推进。本次交付和验收范围为交互原型。
