# RINGS 信息架构（Information Architecture）

> 状态：结构建议。已确认默认首页是可视化调度工作台；其他导航分组仍需原型评审。

## 1. 导航原则

- 默认进入可视化调度首页。
- 快速捕捉入口在所有主要页面可达。
- 候选事项统一管理，不按十种分类拆成十个独立一级模块。
- 规划层管理 Direction / Goal / Stage。
- 执行层管理 Task / Habit / WorkSession。
- 调度层管理 Plan 和 CalendarEvent。
- Thought、WorkContext 和 Material 作为详情页中的关联区域或侧栏能力，不强制成为一级导航。

## 2. 建议一级导航

| 导航 | 页面编号 | 主要内容 | 能力映射 |
|---|---|---|---|
| 首页 | UI-04-01 | 今日 / 周 / 月 / 年时间工作台 | CAP-04、CAP-03 |
| 候选事项 | UI-01-01 | Candidate Pool、分类筛选、回顾 | CAP-01 |
| 规划 | UI-02-01 | Direction、Goal、Stage | CAP-02 |
| 执行库 | UI-03-01 | 普通任务、习惯、子任务与执行记录 | CAP-03 |
| 复盘与统计 | UI-05-01 | Review、Statistics | CAP-05 |
| 设置 | UI-05-02 | 数据、通知、快捷键、平台设置 | CAP-05、XCAP |

Focus / WorkSession 建议作为任务启动后的工作模式或独立工作面板，而不是默认首页。

## 3. 页面层级

```text
RINGS
├── 首页（可视化调度）
│   ├── 今日 / 本周 / 本月 / 年度
│   ├── 未安排任务池
│   └── 快速创建
├── 候选事项
│   ├── 全部候选事项
│   ├── 按十种分类筛选
│   ├── 待回顾
│   └── 详情（备注 / 补充资料 / 时间 / 关联）
├── 规划
│   ├── 发展方向
│   ├── 目标
│   └── 阶段
├── 执行库
│   ├── 全部执行（Task + Habit 摘要）
│   ├── 普通任务（未安排 / 已安排 / 进行中 / 等待 / 已完成）
│   └── 习惯（今日 / 本周 / 全部 / 暂停中）
│       └── HabitOccurrence 执行记录
├── 复盘与统计
│   ├── 周期回顾
│   └── 统计分析
└── 设置
    ├── 数据与备份
    ├── 提醒与通知
    └── 快捷键与外观
```

## 4. 详情页结构建议

Candidate 详情：基本信息、备注列表、补充资料、时间信息、关联事项、生命周期操作。

Task 详情：基本信息和状态、子任务、Deadline / Plan、WorkSession 历史、Thought Stream、WorkContext、补充资料和关联对象。

Goal 详情：目标指标和完成条件、Stage 列表、关联 Task、里程碑、资料与回顾。

## 7. 首页工作区 v0.7 细化

顶部导航增加“收藏资料”快捷操作，与“新建”并列。该入口保存 Candidate，分类为“资料（Resource）”，可填写名称、URL / 文件路径、标签和上下文备注。

桌面首页由固定工作区头部和内容面板组成：

- 固定：顶部导航、首页标题与摘要、时间安排面板头部、任务池头部、任务池搜索和筛选。
- 独立滚动：时间轴内容、任务池列表、弹窗表单内容。
- 时间安排面板支持全屏专注。
- 任务池标题栏放置“添加任务”，卡片提供快速编辑。
- 新建任务保存后置顶显示。

创建 Goal 时可选建立子 Stage；Calendar Event 的开始时间必填，结束时间可在事件结束后补录。


## 8. 执行库入口合并（2026-11-18）

“任务库”和“习惯”合并为一个一级入口“执行库”，页面内通过“全部执行 / 普通任务 / 习惯”切换视图。此调整只合并页面入口与管理体验，不合并 Task、Habit、HabitOccurrence 领域实体。

- 普通任务筛选：未安排、已安排、进行中、等待 / 阻塞、已完成、已归档。
- 习惯筛选：今日、本周、全部习惯、暂停中。
- 未安排任务池只接收正式 Task；Habit 规则不作为普通任务排期。
- 某次 HabitOccurrence 可以进入调度层安排。
- 页面规格：execution-library-v0.1-spec.md。

## 9. 候选事项页面原型

Candidate Pool 继续作为独立工作区，十种分类通过同一列表筛选，分类与生命周期状态分离。转换为正式对象前必须由用户确认，并保留来源 Candidate。页面规格：candidate-pool-v0.1-spec.md。
