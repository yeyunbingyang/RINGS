# RINGS 用户交互流程

## FLOW-01 快速捕捉候选事项

```text
用户触发全局快速捕捉
    ↓
输入标题 / 粘贴内容
    ↓
保存为 Candidate
    ↓
可选补充分类、备注、标签、资料和时间
    ↓
留在当前页面，不强制跳转
```

## FLOW-02 Candidate 回顾与转换

```text
打开候选事项池
    ↓
选择一条 Candidate
    ↓
判断后续去向
    ├── 保留 / 孵化
    ├── 归档 / 取消
    ├── 关联已有对象
    ├── 转为 Task
    ├── 转为 Direction / Goal
    └── 转为 CalendarEvent
```

转换必须保留来源 Candidate 和必要内容。

## FLOW-03 首页快速创建 Task

```text
首页点击“新建任务”
    ↓
输入标题
    ↓
选择仅创建或立即安排
    ├── 仅创建 → Task 进入未安排任务池
    └── 立即安排 → 选择日期 / 时间段 → 创建 Task + Plan
```

## FLOW-04 未安排 Task 拖放到时间线

```text
未安排任务池选择 Task
    ↓
拖到某日或某时间段
    ↓
创建 / 更新 Plan
    ↓
检查冲突
    ├── 无冲突 → 保存
    └── 有冲突 → 提示用户选择
    ↓
时间线更新
```

拖放不创建重复 Task，不自动改变 Deadline。

## FLOW-05 开始执行

```text
点击时间线中的 Task
    ↓
查看任务详情
    ↓
开始 WorkSession
    ↓
暂停 / 继续 / 结束
    ↓
记录实际投入和结果
    ↓
更新 Task 状态和统计
```

## FLOW-06 Goal / Stage 创建任务

```text
打开 Goal
    ↓
选择 Stage 或直接关联 Goal
    ↓
创建 Task
    ↓
Task 进入执行层
    ↓
Task 可在首页安排 Plan
```

## FLOW-07 文件夹引用

```text
在 Candidate / Task 详情中添加资料
    ↓
选择“引用文件夹”
    ↓
Desktop 文件夹选择器
    ↓
保存路径和显示名称
    ↓
展示引用状态
    ↓
点击打开 / 检查路径 / 重新定位
```

Web 不承诺直接访问本地任意路径。

## FLOW-08 等待事项跟进

```text
Candidate（等待）或 Task（waiting）
    ↓
设置 follow_up_at
    ↓
到期提醒
    ↓
记录回复或检查结果
    ├── 解除等待
    ├── 创建后续 Task
    └── 继续等待并更新跟进时间
```

## FLOW-09 周 / 月 / 年计划细化

```text
年度 Direction / Goal / Stage
    ↓
月度重点和阶段节点
    ↓
周计划分配日期
    ↓
日计划安排时间块
    ↓
实际执行与回顾
```

用户可以从任意时间尺度开始，不强制先有年度计划。


## FLOW-10 顶部快速收藏资料

用户点击顶部“收藏资料”
    ↓
填写资料名称（必填）
    ↓
在快速捕捉表单中可选添加标签、备注、清单和资料
    ↓
保存为 Candidate，分类为“资料（Resource）”
    ↓
按捕捉流程刷新候选事项并显示保存反馈

从「收藏资料」进入时隐藏分类选择。验收时选择文件、拖入文件或粘贴链接，保存后在「资料」分类的候选事项详情核对文件与引用。外部链接或路径只保存引用。

## FLOW-11 任务池快速编辑

用户在任务池任务卡片点击“编辑”
    ↓
打开快速编辑弹窗
    ↓
修改名称、Collection、优先级、预计时长、Deadline
    ↓
可选编辑子任务列表和上下文备注
    ↓
保存并刷新任务池卡片及关联 Plan 摘要

编辑按钮与拖拽、安排操作互相独立。

## FLOW-12 Task 创建后的下一步

创建 Task 并保存
    ↓
判断 Task 是否已有 Plan
    ├── 暂不安排 → Task 进入未安排任务池 → 用户之后选择 Task 并确认日期 / 时间
    └── 已经安排 → 保存当前 Plan → 可选继续安排下一项 → 默认建议从当前时间块结束时间接续 → 用户确认后保存下一项 Plan

## FLOW-13 Goal 与可选 Stage

创建 Goal → 填写基本信息 → 可选添加多个 Stage → 编辑、删除或排序 → 保存 Goal。

未添加 Stage 不阻止 Goal 保存；Stage 不自动转为 Task。

## FLOW-14 Calendar Event 结束时间补录

创建 Calendar Event → 填写事件日期和开始时间 → 结束时间可留空 → 保存并标记“结束待补” → 事件结束后从事件卡片补录实际结束时间 → 更新事件实际时长。

未补录前不得将视觉占位时长视为真实结束时间。


## FLOW-15 执行库统一入口与对象视图

用户打开“执行库” → 选择“全部执行 / 普通任务 / 习惯”：
- 普通任务视图：按未安排、已安排、进行中、等待 / 阻塞、已完成筛选 Task。
- 习惯视图：按今日、本周、全部习惯、暂停中筛选 Habit。
- 全部执行视图汇总展示 Task 与 Habit 摘要，但卡片必须保留对象类型标识。

页面入口合并，不合并 Task 与 Habit 的领域实体，也不将 Habit 规则转换为普通 Task。

## FLOW-16 新建普通任务

用户点击“新建执行事项” → 选择“普通任务” → 输入标题（必填）→ 可选填写说明、Collection、Tag、优先级、预计时长、Deadline、父子任务、Goal / Stage 关联和上下文备注 → 保存为 Task。

默认不创建 Plan；用户主动安排时间后才进入首页时间线。表单不提供“执行方式”选项。子任务可按列表添加、编辑和排序。

## FLOW-17 新建习惯与记录执行

用户点击“新建执行事项” → 选择“习惯” → 输入名称和重复规则 → 可选设置开始日期、量词目标（数值 + 单位）、提醒、Collection、Tag 和说明 → 保存 Habit 规则。

在今日 / 本周视图中选择某次 HabitOccurrence → 记录完成、跳过或更新量词结果。记录作用于单次实例，不修改 Habit 重复规则。

HabitOccurrence 的预生成策略、补记录规则和统计口径仍待领域决策。

## FLOW-18 Candidate 回顾与分流

打开 Candidate 详情 → 查看分类、状态、备注、补充资料和时间信息 → 选择保留、孵化、关联、转换、归档或取消。

转换前选择 Task / Goal / CalendarEvent，预览字段映射并由用户确认。转换成功后保留原 Candidate、备注、标签、附件和外部引用，并建立来源关系。

## FLOW-19 Candidate 转为 Task

Candidate 详情 → 点击“转为 Task” → 预填标题、描述和标签 → 用户确认并补充 Task 字段 → 创建正式 Task → Candidate 标记为 converted → Task 进入执行库的普通任务视图。

新 Task 默认未安排；之后由用户创建 Plan。Candidate 不因存在 Deadline Hint 而自动转换或自动排期。


## FLOW-20 编辑普通任务

执行库选择普通任务 → 打开详情 → 点击“编辑” → 在编辑表单中修改标题、说明、优先级、预计时长、Deadline、Collection 和子任务 → 保存 → 更新原 Task。

编辑不得自动创建 Plan，不得重置 Task 状态或已完成子任务计数。

## FLOW-21 编辑习惯规则

执行库选择习惯 → 打开详情 → 点击“编辑规则” → 修改名称、说明、重复规则和量词目标 → 保存 → 更新原 Habit 规则。

编辑规则不修改既有 HabitOccurrence 记录；量词数值与单位必须同时填写或同时留空。


## FLOW-22 创建 Direction 与 Goal

打开规划工作区
    ↓
可选创建 Direction（方向可以独立存在）
    ↓
创建 Goal
    ↓
填写名称、说明、衡量方式、期限和完成条件
    ↓
可选添加多个 Stage
    ↓
保存 Goal
    ↓
不自动生成 Task 或 Plan

## FLOW-23 Goal / Stage 关联执行任务

打开 Goal 详情
    ↓
选择创建 Task 或关联已有 Task
    ↓
选择直接关联 Goal，或指定一个 Stage
    ↓
保存关联
    ↓
Task 仍由执行库管理
    ↓
新建 Task 默认进入未安排任务池，由调度首页创建 Plan

解除关联只移除 Goal / Stage 关系，不删除 Task。

## FLOW-24 Goal 指标更新与完成确认

Goal 详情
    ↓
根据指标类型更新数值 / 里程碑 / 布尔结果 / 自定义进度
    ↓
单独查看关联 Task 完成率
    ↓
用户判断目标是否达成
    ↓
明确标记 Goal 完成

Stage 全部完成不自动将 Goal 标记为完成；Task 完成率不直接作为 Goal 进度。
