# RINGS UI / UX 设计规范（初稿）

> 状态：交互原则已部分确认；视觉设计系统和具体布局待原型评审。

## 1. 设计目标

- 让用户快速捕捉，不被复杂表单阻断。
- 让“候选 / 规划 / 执行 / 调度”语义清楚。
- 让时间安排可视、可拖放、可撤销。
- 让长期计划与每日执行保持联系，但不强迫全部事项都进入目标体系。
- 支持键盘操作和鼠标操作。
- Desktop 优先考虑宽屏工作台；Web 适配较窄视口。

## 2. 视觉方向

RINGS 品牌意象为“年轮、积累、生长”。可以探索同心环、层叠纹理、柔和自然色系等视觉语言。

尚未确认：最终主色、字体字号、圆角阴影、Logo、深色模式。V2.0 原型的暖色背景和卡片风格可作为历史参考，不是强制设计规范。

## 3. 核心交互原则

1. 快速创建尽量只要求标题。
2. 详情信息分区呈现，避免首屏过长。
3. 状态、分类和时间语义必须可辨识。
4. 拖放提供明确目标区域、悬停反馈和落点预览。
5. 拖放必须提供非拖放替代操作，例如“安排到日期”菜单。
6. 时间冲突不能静默覆盖。
7. 归档、取消、删除必须有不同文案和确认策略。
8. 文件附件与外部引用必须在 UI 上明确区分。
9. 失效路径要保留并提供重新定位。
10. 快捷键不能成为唯一操作方式。

## 5. 状态设计

所有核心组件至少考虑默认、Hover / Focus、Selected、Dragging / Drop Target、Loading、Empty、Error、Disabled 和 Read-only 状态。

## 6. 首页 UI 要求

- 显示当前日期和当前视图。
- 日 / 周 / 月 / 年切换位置稳定。
- 快速创建入口容易发现。
- 时间线是主要视觉区域。
- 未安排任务池可折叠或调整宽度。
- Task 卡片显示标题、预计时长、Deadline、优先级和目标归属（可选）。
- Plan Block 显示计划时段，不把 Deadline 当作执行时间。
- 习惯和日历事件采用可区分的视觉样式。
- 当前时间线有“现在”指示。
- 支持键盘安排任务的替代流程。

## 7. Candidate UI 要求

- 一个统一候选池。
- 十种分类作为筛选条件。
- 显示格式为中文名称（English）。
- 标题优先，备注可展开。
- 补充资料显示文件类型和引用状态。
- 不显示强制清空率。
- 支持批量归档和标签调整。

## 8. 文件与路径 UI 要求

- “上传副本”与“仅保存引用”使用明确文案。
- 本地路径显示为外部引用，不伪装成已上传附件。
- 文件夹引用显示路径和可用状态。
- 失效引用提供“重新定位”。
- 不在没有授权时扫描或上传目录内容。

## 9. 响应式与可访问性

- 桌面端优先使用多栏布局。
- Web 窄屏允许任务池切换为抽屉或独立面板。
- 拖放应提供菜单或键盘替代操作。
- 状态不能只靠颜色表达。
- 交互控件应有可见焦点状态。
- 日期和时间输入应可键盘操作。

## 10. 待原型确认

所有组件尺寸、颜色、间距、字体、动画和断点以 HTML 原型评审结果为准；当前文档不锁定具体像素值。
