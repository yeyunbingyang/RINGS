# RINGS 候选事项页面设计规格 v0.1

> 日期：2026-11-18  
> 状态：页面结构与交互方案首版；等待原型评审。  
> 能力映射：CAP-01、CAP-05。  
> 领域边界：Candidate 是尚未正式分流的统一候选事项；不等于 Task，也不等于资料库或日历事件。

## 1. 页面目标

建立一个统一的“候选事项（Candidate Pool）”工作区，用于收集、澄清、回顾和分流尚未形成正式承诺的信息。

页面不要求用户立即决定每条信息的去向，也不以“清空收件箱”为目标。Candidate 可以长期保留、孵化、关联或归档。

## 2. 十种分类与状态

### 2.1 固定分类

分类回答“这是什么”，采用单一主要分类 + 自定义 Tag 的方式呈现：

1. 备忘（Memo）
2. 资料（Resource）
3. 想法（Idea）
4. 愿望（Wish）
5. 待办种子（Task Candidate）
6. 问题（Issue）
7. 待决策（Decision）
8. 承诺（Commitment）
9. 事件（Event）
10. 等待（Waiting）

十种分类作为页面筛选器，不拆分为十个一级页面。

### 2.2 生命周期状态

状态回答“现在如何”，与分类独立：
- 新收集（new）
- 待澄清 / 回顾中（reviewing）
- 保留（retained）
- 孵化（incubating）
- 已转换（converted）
- 已归档（archived）
- 已取消 / 不再处理（dismissed）

默认工作视图优先展示 new 与 reviewing；已转换、归档和取消对象可通过筛选查看。

## 3. 页面布局

桌面端采用“顶部工具栏 + 左侧筛选 + 中间列表 + 右侧详情”的三栏布局：

### 顶部固定区
- 页面标题“候选事项”。
- 简短说明：“先收集，再判断；不要求每条信息立即变成任务。”
- 统计摘要：待回顾、孵化中、已保留、资料引用。
- 快速捕捉按钮。
- 搜索、排序和批量操作入口。

### 左侧筛选栏
- 全部候选事项。
- 待回顾。
- 孵化中。
- 已保留。
- 已转换。
- 已归档。
- 十种分类筛选。
- Collection / Tag 筛选。
- 时间筛选：最近收集、近期需跟进、已过跟进时间。

### 中间列表
默认按最近更新时间倒序；用户可切换最近创建、跟进时间、名称排序。

Candidate 卡片展示：
- 标题。
- 分类标签（中文名称 + English）。
- 生命周期状态。
- 内容摘要 / 最近一条备注。
- 自定义 Tag。
- 来源提示（网页、文件路径、手动输入等）。
- 跟进 / 回顾时间（若有）。
- 最近更新时间。

卡片操作：
- 打开详情。
- 标记保留 / 孵化。
- 转换为正式对象（根据语义显示适用目标）。
- 归档 / 取消。
- 多选批量归档、批量调整 Tag。

### 右侧详情
分区：
1. 基本信息：标题、分类、状态、来源、创建 / 更新时间。
2. 备注记录：多条备注，支持新增、编辑、删除、排序。
3. 补充资料：Managed Attachment 与 External Reference 分开展示。
4. 时间信息：Deadline Hint、Event Time、Reminder Time、Follow-up Time、Review Time。
5. 关联事项：相关 Candidate、Goal、Task、CalendarEvent 等。
6. 生命周期：保留、孵化、转换、归档、取消。

## 4. 快速捕捉

快速捕捉只要求标题 / 内容，其他信息可稍后补充。

可选字段：
- 主要分类（默认“备忘 Memo”或用户上次选择）。
- 标签。
- 上下文备注。
- 网页链接 / 文件路径 / 文件夹引用。
- 跟进时间 / 回顾时间。

顶部“收藏资料”快捷入口仍然只是 Candidate 快速捕捉的轻量入口，默认分类为“资料（Resource）”，不建立第二套资料实体。

外部引用仅保存 URL / URI / 路径；不自动读取、复制、上传或扫描源文件。

## 5. Candidate 回顾与分流

用户打开 Candidate 后，按内容决定下一步：

| 操作 | 适用情况 | 结果 |
|---|---|---|
| 保留 | 仍有价值，但暂不推进 | status = retained |
| 孵化 | 有潜力，等待条件成熟 | status = incubating，可设 Review Time |
| 关联 | 与已有 Goal / Task / Candidate 等有关 | 建立 Relation，不改变对象类型 |
| 转为 Task | 已明确要承担并执行的行动 | 创建 Task，保留来源 Candidate |
| 转为 Goal / Direction | 已明确为结果目标或长期方向 | 创建对应规划对象，保留来源关系 |
| 转为 CalendarEvent | 已确认具体发生日期 / 时间的事件 | 创建 CalendarEvent，保留来源关系 |
| 归档 | 暂时退出日常视图，但可能恢复 | status = archived |
| 取消 | 明确不再处理 | status = dismissed |

**禁止的隐式转换：**
- 仅因 Candidate 有 Deadline Hint，不自动创建 Task。
- Candidate 的“事件 Event”分类不自动创建 CalendarEvent。
- Candidate 不直接进入首页未安排任务池或时间线。
- Candidate 转为 Task 必须由用户确认；转换后才可安排 Plan。

## 6. 转换交互

点击“转为正式对象”后打开转换面板：
1. 选择目标类型：Task / Goal / Direction / CalendarEvent（只显示语义适用项）。
2. 预填 Candidate 标题、描述、标签和可迁移的时间信息。
3. 用户确认并补充目标对象所需字段。
4. 保存后建立来源关系，Candidate 状态标记为 converted。
5. 详情中展示“已转换为 …”链接，可回看来源内容。

转换不应删除 Candidate，不应丢失备注、标签、附件和外部引用。无法迁移的字段保留在原 Candidate。

## 7. 搜索、筛选和批量管理

- 全局搜索标题、内容和备注。
- 分类与生命周期状态可以组合筛选。
- Tag 与 Collection 可以叠加筛选。
- 时间筛选区分 Follow-up Time 与 Review Time。
- 支持多选批量归档、恢复、添加 / 移除 Tag。
- 批量操作不提供批量转换，避免误将不同语义的 Candidate 转为同一种对象。

## 8. 空状态与提醒

- 空列表：说明当前筛选下没有 Candidate，提供“快速捕捉”入口。
- 待回顾：显示待回顾数量和最早待处理时间，不显示强制清空率。
- 逾期跟进：只提示 Follow-up Time 已到，不自动改变 Candidate 状态。
- 长期保留：不因停留时间过长而自动归档或删除。

## 9. 响应式

- 桌面端：三栏布局。
- 平板：左侧筛选可折叠，详情按需展开。
- 手机：筛选抽屉 + 单列列表；详情独立页面 / 抽屉。
- 列表操作必须有明确按钮，不依赖 Hover 才可发现。

## 10. 原型验收清单

- [ ] 十种分类可在同一列表筛选。
- [ ] 分类与生命周期状态分别展示。
- [ ] 快速捕捉只要求标题 / 内容即可保存。
- [ ] 支持多条备注、标签、时间信息和补充资料。
- [ ] Managed Attachment 与 External Reference 明确区分。
- [ ] 资料收藏入口保存为 Resource Candidate。
- [ ] Candidate 不进入未安排任务池。
- [ ] 转换为 Task / Goal / Direction / CalendarEvent 前需要用户确认。
- [ ] 转换后保留来源关系和原始 Candidate。
- [ ] 归档可恢复；取消不等于删除。
- [ ] 不设置每日清空率或强制 Inbox Zero 机制。

## 11. 未决策事项

- Candidate 分类是否严格单选（当前页面按单选设计）。
- Candidate 回顾提醒默认频率。
- 批量编辑是否支持批量改状态。
- Managed Attachment 的存储策略与附件大小限制。
