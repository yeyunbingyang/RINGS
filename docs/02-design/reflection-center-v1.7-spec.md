# RINGS v1.7 复盘中心 UI / UX 规格

## 页面目标

让用户先看清本周期实际发生的事实，再填写复盘判断，最后把改进转化为下一周期行动。统计与复盘分离，避免图表和表单相互干扰。

## 页面结构

一级入口沿用「复盘与统计」，页面标题使用「复盘中心」。

标签顺序：
1. 周期复盘（默认）
2. 数据分析
3. 历史复盘
4. 改进追踪

### 周期复盘

- 顶部：周期类型、范围、上一周期、下一周期。
- 默认周期：自然周，周一至周日。
- 周期摘要：复盘状态和日期范围。
- 周期事实：任务与计划、时间投入、习惯记录、目标变化四块信息卡。
- 复盘表单：成果、偏差、原因、经验、下一周期行动五个区块。
- 底部操作：保存草稿、完成本次复盘。

### 数据分析

独立展示 KPI、每日计划与完成趋势、Plan 执行结果、Session 时间质量、Habit 实际记录和业务变更历史。所有图表必须附统计口径说明。

### 历史复盘

按周期倒序排列。每项显示周期范围、草稿 / 已完成状态、更新时间和查看 / 编辑操作。

### 改进追踪

列表显示改进事项、来源复盘、当前状态。支持新建、完成 / 重新打开、删除。

## 视觉规范

- 沿用 RINGS 现有浅色背景、白色卡片、低饱和绿色强调色、细边框和圆角。
- 不重构全局导航、顶部栏和其他业务页面。
- 统计卡片只强调关键数字，不堆叠多余装饰。
- 事实卡与用户输入表单视觉分组清晰。
- 表单标签、输入框和卡片边缘统一对齐。
- 长文本框允许垂直调整大小；移动端单列布局。
- 周期切换控件在窄屏自动换行，避免挤压标题。

## 数据展示规则

- Task 与 Plan 分开计数。
- 计划分钟数与 Session 实际分钟数分开。
- 精确、估算、未记录采用文字标识，不仅依赖颜色。
- 未记录不可显示为零完成。
- 目标当前进度需注明“当前状态”。
- 升级前不可追溯的历史明确标注，不生成虚构曲线。

## 交互状态

- 草稿：允许保存、继续编辑。
- 已完成：允许查看和再次编辑；更新时间更新。
- 空状态：说明暂无历史复盘 / 暂无改进项，并提供创建入口。
- 数据不足：显示“暂无可计算数据”，而非 0%。
- 删除改进项需二次确认（正式产品实现要求）。

## 响应式验收

- 桌面：事实卡两列，KPI 四列。
- 窄屏：事实卡、表单、KPI 单列或两列紧凑布局。
- 390px 视口无横向溢出。
- 周期切换、标签、草稿保存和历史查看可触达。
